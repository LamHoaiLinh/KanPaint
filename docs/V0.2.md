# KanPaint v0.2

## Interface
KanPaint keeps the OpenShop/Photoshop-style layout: top menus, left toolbar,
canvas in the center, panels on the right. New workflow entry points are kept
where Photoshop/Photopea users expect them:

- File > Export Layers...
- File > Scripts > Run Script...
- File > Scripts > Script Library...
- Left toolbar > Skin Retouch (SR)

## Export Layers
Exports visible, selected, or all non-empty layers as transparent PNGs.
Auto Trim scans alpha and removes transparent margins. Padding is optional.
Multiple files are downloaded as one ZIP. Layer names become filenames.

## Script Engine
Scripts run in an isolated sandbox iframe. They do not get direct DOM, network,
or filesystem access. The v0.2 allow-listed API exposes document information,
layer listing/export/rename/visibility, selection information, and toast UI.

The Script Library contains built-in recipes and user scripts saved locally.
User scripts can be created, edited, deleted, imported, backed up, and restored.
Limits: 50 user scripts, 256 KiB per script, 2 MiB total library.

## Skin Retouch
Skin Retouch is brush-mask based and can be clipped to an existing selection.
Controls:

- Size, Hardness, Flow
- Amount (master strength)
- Smooth
- Light / Dark
- Shadow Lift
- Shine Reduce
- Texture / Pores
- Detail Preserve
- Hold: Before
- Apply / Cancel

Slider values update immediately while dragging; the image preview is rendered
when the slider is released. Large images use a preview proxy capped at about
1.2 MP; Apply renders once at full resolution and creates one history step.

## Risk controls built into v0.2
1. Core-growth risk: KanPaint additions live in separate JS/CSS extension files;
   the upstream monolithic core is not enlarged.
2. 4K/8K lag risk: preview proxy + release-to-render + one full-resolution Apply.
3. Plastic-skin risk: edge-aware smoothing, Detail Preserve, original-detail
   restoration, and a separate Texture/Pores control.
4. Script risk: sandbox iframe, no same-origin permission, an allow-listed API,
   script time/size/library limits, and no direct network/filesystem bridge.
